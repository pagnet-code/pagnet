# Explicit installed service runtime

`InitializeServiceState` is an explicit protected-operator setup action. It creates the same-root invocation configuration and empty startup manifest in one signed FULL transaction; repeated initialization fails. `NewServiceRuntime` only opens retained state, validates its fixed capacities/key and all operator-selected private profile commitments, then starts a bounded number of owned connection workers. It never bootstraps missing state, infers connections from catalog descriptors, installs providers, or executes tools at startup.

`Connect(scope, bootstrapCatalog)` verifies the actual protected installation operator, pins the exact selected profile/account/endpoint revision into the encrypted startup manifest, and then opens the maintained MCP/A2A SDK binding. First MCP catalog creation is an explicit setup choice. Later startup opens that retained catalog. An external connection failure remains a selected unavailable service; other services and local search/native operations are independent. Its resolver cannot choose an alternative endpoint or initiate another handshake. Supported SDK protocol versions are registered once, so explicitly connecting another service does not require per-agent attachment or mutate routing authority.

The startup manifest contains at most256 selected scopes and account/profile commitments. It is encrypted under the installation key, split into pages of at most16 choices, and signed by the actual retained root. Header count/generation/digest and page generation agree atomically; at most64 indexed authority operations and5seconds bound a mutation. Opening verifies the entire finite manifest before exposing connections. Explicit choice removal affects future startup; retained authority/replay history is never deleted. Full valid storage rollback needs an external monotonic witness, as with the underlying registry.

The actual `LocalBoundary` performs current kernel/session checks before dispatch and consumes exact source facts under the invocation transaction. A2A's disclosure gate checks that same genuine current caller and selected destination. SDK credentials stay behind the explicit private provider, outside Root SQL and outside public catalog/index/event data. Setup authority cannot become a caller's authority.

`CloseContext` cancels SDK transports before joining setup workers. It reports an incomplete join on caller deadline and retains resources, allowing another close attempt before the Store/key is released. Root's InstalledNode assembly must combine this resource with the native runtime and join transport sessions before closing both. No background reconnect or paid effect retry is provided.

Verification uses a protected local installation, genuine current boundary, and two actual official MCP SDK servers. Explicit setup persists both choices without tools/call; restart reconnects one healthy service while the other real endpoint is offline, leaves that exact target unavailable, and closes without provider effects. Separate manifest tests cover protected paged state, actual registry close/reopen, capacity, cancelled writes and inconsistent signed pages. Canonical cross-request idempotency/replay associations belong to the independently coordinated next packet.
