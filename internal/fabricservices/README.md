# Installed service bindings

This private node composition uses the **same retained registry Store** for encrypted service profiles, MCP tool catalog projections, and signed FULL service invocation receipts. It creates no second root, token namespace, replay database, public URL catalog, or workflow planner. Credentials are resolved through an explicit operator-private provider outside SQL and never stored in profiles, descriptors, indexes, invocation envelopes, or event metadata.

`ProfileStore.Install` selects an exact already-published endpoint/binding/revision, protocol/version, account/profile digest, and credential selector. HTTP addresses and A2A Agent Cards remain encrypted private configuration. Stdio runs an absolute installed executable with explicit arguments and memory-only credential environment, without a shell or inherited shell environment. URLs reject credentials, query parameters, fragments and unselected HTTP. Profiles are immutable: exact setup retries return the retained generation; changing account, URL, executable, interface, or limits requires a new published binding. Missing/wrong-key retained state never initializes through `Get` or `Open`.

MCP uses the maintained official SDK through `ConnectMCP`/`Sync`, and the existing same-root encrypted MCP catalog. `bootstrapCatalog=true` is explicit first installation; later connections open that actual catalog. One connection/catalog is shared by authorized callers, not attached separately per agent. Router selection performs no connection, spawn, discovery, provider lookup or fallback. MCP requires a specific published offer, not an endpoint that silently chooses a tool. The negotiated SDK version must equal the installed advertised binding version. Background tool-change synchronization preserves actual stable offer IDs and revisions; invocation rechecks actual current offer schema and profile inside the admission transaction.

A2A selects exactly `a2a.jsonrpc` / `1.0`, an operator-selected private interface and trusted installed Agent Card. The official adapter supplies the genuine SDK HTTP/events, precision-preserving raw records, bounded pull stream, and explicit task status semantics. `A2AAssociations` implements its protocol-local task/context map in the **same root invocation ledger**, not the optional standalone adapter SQLite store. A new get/subscribe/cancel request must select a retained owned original invocation; its current caller/policy is independent of that old invocation. Task IDs are adapter protocol associations, not Pagnet planning state.

## Admission and output fidelity

`BootstrapInvocations` is explicit; `OpenInvocations` requires the same authenticated configuration/key. `Reserve` requires the actual private `node.FinalizedRequestFromContext` capability, authenticates the original bytes, matches the passed request exactly, compiles the selected offer schema outside SQL, and checks the current target, profile fingerprint and **mandatory current policy** under the same signed root transaction. No plaintext wire principal creates that capability. The root signs its closed finalized dispatch purpose before committing the first-attempt receipt.

Replay identity is the domain-global full principal ref/kind/issuer plus original invocation ID, independent of target, revision, binding, account or caller replay labels. A changed retry is denied. An explicit idempotency key additionally creates a domain-global full-principal/key fence in that same transaction. Fresh request IDs bind a signed alias to the immutable original admission; changed target/revision/input/private account is denied. Current requester authorization and deadline stay independent from the original execution, whose paid deadline is never renewed. Replay frames retain their original invocation ID and sequence. `Invocations` implements the mandatory node `ReplayVerifier`: exact current alias/index/original receipt and real root dispatch signature are verified together with current history policy. A historical public signature alone grants no access. Association hashes, account fingerprints and opaque proof are private response metadata for the same authenticated caller over local/encrypted transport, never catalog/search/event/telemetry/relay metadata. Native or other bindings without this capability continue to reject keys before effects. Standalone A2A defaults to no idempotency; actual signed service-ledger composition explicitly opts in and never emits remote idempotency headers. FULL intent commit precedes any SDK effect; SQL admission and remote execution are separate, with no distributed atomicity claim. An uncertain attempted call is never sent again. A genuine terminal original result replays its actual retained ordered frames; a lost/unobserved outcome stays explicitly unknown. Crash, EOF, cancellation, capacity or an ACK cannot fabricate completion.

Original frames are committed before delivery, with exact invocation/ordinal, lifecycle ordering, authenticated chunks and byte digest. One frame is read by indexed key with bounded chunks; there is no whole-response buffer or history scan. Identical checkpoint retries are idempotent; changed bytes, foreign invocation, gaps, content after terminal and invented terminal shapes are refused. Original frame bytes including binary/UTF8 splits are preserved. Frames remain retained; this version does not reclaim them and consequently has no pretend consumer ACK/purge semantics. Capacity exhaustion fails closed rather than deleting replay fences.

Defaults: 65,536 combined original receipts, idempotency fences and current-request aliases, 262,144 frames, 256 MiB cumulative protected application records, and 4,096 frames per original. Each plaintext authority value is at most 32 KiB and protected JSON at most 64 KiB; a genuine canonical frame is stored in at most six 16 KiB plaintext chunks. Shared registry record/ledger/database quotas also apply and may be reached first. Counters/configuration update in the same FULL transaction. No request scans all invocations. Retained-root startup integrity is registry-owned; whole valid storage snapshot rollback still requires an external monotonic witness to detect.

## Current authorization boundary

Production must inject genuine current `OwnerProvider`, `InvocationPolicy.AuthorizeTx`, and A2A disclosure/credential providers. There is no permissive default or implicit service privilege. Policy runs bounded local validation under SQL and cannot perform provider/network IO or reopen the same Store. The actual dispatcher must preflight fresh local kernel/session/native-owner evidence outside SQL and supply its private context stamp, while policy consumes current signed source/permission facts in the transaction. Returned streams retain that dispatcher context; caller-supplied `Next` contexts supply cancellation only, not authority. Static reconstructed historical contexts cannot become current authentication. The genuine `fabricnode.LocalBoundary` supplies this policy from actual local session evidence, including independently selected A2A original-task reads. Package unit tests explicitly pin a fixture owner; separate node integration fixtures use a protected installation and real Unix kernel-verified sessions through the actual dispatcher. Product CLI/localinstallation startup assembly remains independently owned.

MCP connections own official SDK session lifetime independently of transient setup contexts. Every HTTP request is additionally bound to node ownership, preventing detached SDK cleanup requests from surviving node shutdown. Default proxy inheritance and redirects are disabled; connection/header/pool limits are finite. Close cancels and joins pending setup and owned sessions. Credentials must report the same trusted account/profile digest on every actual use; token rotation is permitted within that account, while account changes cannot reuse the earlier connection.

## Retained installation setup and live catalogs

The installed node reads a separate encrypted signed services setting from its existing root. Explicit `fabricnode.InitializeConfiguredServices` commits the setting, invocation configuration and startup header together. All three absent means intentionally native-only; a partial, retired, wrong-key or mismatched setup fails closed. `OpenInstalled` never bootstraps service state or changes immutable `installation.json`. Finite limits and the selected provider survive restart. The reserved `credentials.none` provider accepts only profiles explicitly selecting `none`, emits no credential headers and ignores ambient environment. Named providers require explicit injection; an absent provider leaves that selected service unavailable while local discovery/native work remain usable.

Catalog notices carry no descriptor or credential data. The actual SDK catalog invokes the nonblocking notice only after its registry commit; initial connection and background tool changes use the same hook. The installed node's bounded coalesced index publisher drains real committed deltas, including catalogs added after startup, without discovery-time scans, database polling or manual synchronization. Native-only installations also own that publisher for explicit local administration.

Operation cancellation remains separate from session cleanup. Stateful SDK shutdown sends only its exact configured session-bearing DELETE using a separate five-second cleanup lifetime; POST/GET/tool operations still obey node cancellation. A DELETE is neither a tool retry nor proof that arbitrary remote work stopped. Actual provider cancellation uses the maintained SDK's request cancellation semantics; unknown remote outcomes remain unknown.
