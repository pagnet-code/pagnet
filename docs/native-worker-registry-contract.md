# Detached daemon worker registry

Production daemon integration can use these owner-local helpers directly:

1. OpenNativeWorkerRegistry(stateDir); exclude Owns(instanceID) rows from legacy restart reconciliation before recovering agents. Owns fails closed on database errors. List fails on corrupt rows and is bounded to 4096 owners.
2. Dir(scope) derives the private worker namespace. Prepare the launch profile with ContextStateDir equal to this worker directory and NetworkStateDir equal to the daemon's network state. Reserve(scope, spec, profile, originalOwnershipID) records exact authenticated server/account/tenant/host/instance/generation, immutable profile fingerprint and optional original ownership before launch. Repeated identical reservations are idempotent; generation, profile and original ownership changes fail.
3. EnsureNativeWorker(ctx, registry, record, unifiedBinary, runtimeEnv) creates the private bootstrap/key and atomically claims a single launch. It passes environment only through inherited pipe fd3 and uses a detached session/process group. It inherits no controller credentials, sockets or stdio. Startup cancellation closes the pipe and preserves any process that already started. A proven Start failure permits retry; uncertainty or a missing launched socket never permits automatic replacement.
4. AttachNativeWorker remains mandatory for fresh remote admission, mutually authenticated private IPC, profile/scope snapshot proof and controller lease fencing. Ensure's private socket readiness alone is not authenticated ownership or native-session proof. The original native process cannot start until the existing backend activation gate completes.
5. After successful backend registration AND worker ownership binding, BindOwnership stores the exact validated original ownership reply once. This helper is local durability, not a substitute for either remote commit or worker binding. The original identity and admission are immutable; later validated backend receipts can advance dispatch/floor counters monotonically under a transaction. Locally invented counters are not accepted as a replacement for backend receipt validation.

The registry and private manifests omit runtime environment (`NativeSpec.Env` is excluded from JSON and the profile fingerprint). SQLite WAL with FULL synchronous commits retains original reservations and launch state across daemon replacement; directory creation is synced before detached launch. Existing symlinks, writable or foreign-owned daemon state parents, non-private worker directories/files and overlong Unix socket paths fail closed. An existing owner-controlled 0755 daemon parent is accepted without changing its permissions; the native-workers child and individual worker directories remain 0700. Namespace uses a 128-bit digest while every load compares the complete scope and profile. The controller socket path must fit the shared Linux/Darwin 103-byte bound; configure a shorter private state root if necessary.

The helpers never scan, adopt, signal or kill arbitrary PIDs, and registry Close does not stop detached workers. No automatic crashed-worker restart or ownership generation rotation is provided: these require explicit backend retirement and original lifecycle settlement. A crash during launch leaves the namespace owned and blocked instead of risking a duplicated original process.

Actual process gates launch a built pagnet session worker from a separate launching controller subprocess, let that controller exit, reopen the registry, authenticate a fresh controller and verify the same kernel peer PID and detached process group. Wrong-key authentication cannot evict the valid lease. Durable scope/profile/ownership conflict, symlink rejection and environment non-persistence gates are automated; no live server/provider call is made.
