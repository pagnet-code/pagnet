# Retained extension configuration

This package manages encrypted extension installations in the **existing local registry's signed FULL SQLite ledger**. It does not create another database, signing root, endpoint offer or native binding. `Bootstrap` explicitly installs an empty directory; `Open` requires the retained directory and referenced entries. Neither regenerates missing state or encryption keys.

The operator supplies the actual retained `registry.Store`, an external stable `durable.DataProtector`, and a mandatory live `OwnerValidator`. Every management operation also verifies the authenticated caller's exact root owner and audience and the store's current identity. Private provider selectors and credential-principal references are encrypted; actual provider credentials are resolved separately and must not be embedded in installation metadata. This package does not install providers or implement handlers.

`Install`, `Update` and `Remove` require exact directory generation and entry revision. A candidate's complete manifests, bindings, placement rules and interceptor dependency DAG are validated and compiled before an atomic signed transaction changes the encrypted directory and entry (or permanent tombstone). Removal followed by deliberate installation creates a new physical identity. A successful commit is read back exactly before publishing the snapshot. An uncertain commit or detected external revision change quarantines the facade until authenticated `Reload` succeeds.

`Snapshot` reads an immutable atomic cached plan: no database reads, registration scans or compilation occur on invocation. Its revision commits to both manifests and actual private bindings, retained entry revisions and configuration generation, so changing a provider rejects an old deferred pipeline. Existing accepted snapshots may finish during an update; partially committed candidates never become visible. Compose one management facade for a node: separate authorized writers must coordinate changes and `Reload`; cached snapshots are not an independent database filesystem monitor. Close the facade before closing the shared root store. Closing this facade never closes that shared store.

Default capacity is 64 active extensions and 512 interceptors; explicit configuration allows at most 128 extensions and 4096 interceptors. Each plaintext entry and directory is limited to 32 KiB, encrypted records to the existing 64 KiB authority limit. Existing signed ledger history/operation/byte limits may be tighter and remain authoritative. Pagination cursors pin the configuration generation. Historical signed records and removal tombstones consume finite ledger capacity; no silent purge or unlimited-registration promise is made.

Restart requires the same retained root, configured limits and external encryption key. Wrong keys, missing entries, malformed manifests, ciphertext substitution and revision disagreement fail closed. This is local encrypted configuration, not a claim that all registry data is encrypted at rest or that cloud synchronization is already composed. Interceptors, event subscriptions and triggers remain separate semantics; product composition must supply the genuine handler and action/event ports.
