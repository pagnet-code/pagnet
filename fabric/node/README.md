# Trusted node operation composition

Every operation authenticates the exact original bounded envelope before creating
the private in-process caller/original-request capability. Discover and describe
receive read ports; only invoke receives the exact-target dispatcher. No read
operation can resume work, emit an invocation or select a fallback target.

An explicitly configured extension engine provides discover.request,
describe.request, discover.response and describe.response stages. The hybrid
candidate composition separately runs discover.candidates before external model
disclosure. Its inputs remain owned, authenticated projections, not wire caller
claims about intermediate stages.

Read interception requires an explicit current `ValidateReadResult` implementation
from trusted registry/disclosure composition. Even a cache's RESPOND shortcut
passes result shape validation, current disclosure validation, the response-stage
chain and final current disclosure validation. Schemas/references/revisions and
offer pages must match the selected describe request. Response streams and
deferrals are rejected for read operations; they cannot turn discovery into work.

The current authority validator is a port, not an automatic permission policy.
Production daemon/session/registry composition must supply it. Unit conformance
fixtures prove these boundaries but do not establish a deployed local node.
