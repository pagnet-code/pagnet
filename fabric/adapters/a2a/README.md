# Explicit A2A1.0 JSON-RPC adapter

This package implements `fabric.EndpointAdapter` with the official `github.com/a2aproject/a2a-go/v2` SDK v2.6.0 (Apache-2.0). It accepts an explicitly trusted Agent Card and exactly selected JSON-RPC1.0 interface. `WithDefaultsDisabled` removes transport fallback; the private cloned card contains only the selected interface. Streaming is refused before the SDK when not advertised. Other protocols/versions are explicitly unsupported in this profile. No agent-card discovery, model download, provider install or automatic protocol negotiation is added.

The published binding protocol is `a2a.jsonrpc` with version `1.0`; this exact namespaced identifier is also used by the node Router. Construction requires canonical endpoint reference, descriptor revision, private binding ID, mandatory nonzero trusted `BindingDigest` identifying the selected provider principal/profile, audience, explicit credentials/disclosure providers, and durable association store. Invocation requires genuinely authenticated `ExecutionContext`, the exact selected reference/revision/binding, and matching declared streaming/cancellation semantics. Descriptor revision/authority is established by trusted node composition, not remote descriptive text. Standalone idempotency defaults to unavailable: caller keys and transport replay headers are refused. Trusted SAME-root service composition may explicitly enable `RootIdempotency` only with a real `RootIdempotencyStore` that fences aliases before SDK effects; the selected published flag must match. This local execution correlation never emits upstream idempotency headers or claims upstream replay support. Root invocation policy/registry barriers remain mandatory. The credentials provider must honor the declared immutable account/profile selector; rotating its token keeps that selector, changing provider principal changes the digest and private binding fingerprint. Token bytes never become identity. Message IDs hash a typed structure containing the full principal issuer/ref/kind, invocation ID and binding fingerprint, avoiding concatenation and cross-issuer collisions.

## Input and association

Input is `{operation, mode?, parts?, associationInvocation?}`. `send` requires explicit `unary` or `stream` mode and bounded text/data parts; data uses exact raw JSON. `get`, `subscribe`, and explicitly enabled `cancel` name a previously owned Pagnet invocation rather than accepting arbitrary remote task/context IDs. No prior local history, memory, workspace, provider credentials or unrelated tasks are forwarded. History length zero is requested where supported. Remote URI parts are returned as event data and never fetched.

Pagnet node composition uses `internal/fabricservices.A2AAssociations` backed by the same retained registry invocation ledger; it does not create a second replay database. The standalone adapter store below is for explicitly separate embedding applications.

`Bootstrap` creates a new owner-private ledger directory exactly once; `Open` requires the same retained `StoreScope` (actual node domain, stable store identity and authenticated audience), finite `StoreConfig` and stable operator-supplied `DataProtector`. No secret is generated. Missing, corrupt, incomplete or mismatched state fails closed; it is never recreated or healed. All adapters in a node replay namespace must share this retained store. Independent stores cannot provide a cross-store fence.

Admission identity is principal issuer/ref/kind plus invocation ID, independent of target/revision/binding. The encrypted record retains that full original scope, operation/mode and input hash; changed retries conflict, exact retries refuse replay. Before any HTTP effect, FULL-sync SQLite transactions atomically append an authenticated journal entry, update the materialized index and seal the counters/chain head. The first remote task/context association is committed before its event is delivered. An identical association adds no history; changed identities are refused. Explicit get/subscribe/cancel after restart use the owned association and deny other principals, endpoints, revisions and bindings. A connection loss before obtaining a remote identity stays unknown and is never resent.

The ledger retains at most two entries per admission, no message bodies, provider tokens or full descriptors. Defaults bound admissions to65,536, entries to131,072, encrypted journal bytes to64MiB, database bytes to128MiB, plaintext records to16KiB and ciphertext records to20KiB. Startup verifies authenticated empty/current state, complete contiguous journal and exact materialization in pages of64 (maximum128); it is O(N) maintenance with bounded memory. Hot operations use indexed reads and finite budgets. Capacity exhaustion refuses new effects without purging old fences. DELETE journaling and FULL commits avoid a growing WAL. The shared `privatefs` boundary enforces owner-private paths/writer lock including Windows DACL/reparse safeguards. Stable AEAD authentication detects forged records and incomplete materialization; checksums are only chain commitments. A whole previously valid store snapshot rollback needs an external monotonic witness to detect, so this package does not claim to detect it. Deleting the ledger or changing its retained identity/key destroys the replay boundary and must never be used as recovery.


## Event and outcome fidelity

The genuine SDK validates typed events. A bounded transparent HTTP response tap retains the correlated original JSON-RPC result bytes, including integers above2^53 and fields that SDK maps would otherwise round. Unary HTTP bodies are fully read within the finite event/envelope budget and validated as exactly one complete document before the SDK receives them. A valid first chunk followed by another JSON document or garbage is rejected without publishing the prefix; only trailing whitespace is accepted. SSE remains incrementally record-bounded. Output is those exact result records as newline-delimited JSON; a large record can span canonical byte chunks without changing its bytes. Task snapshots, status, messages, artifact IDs, append/replacement and lastChunk fields remain intact and ordered. Unary returns its genuine task/message snapshot, never fabricated stream events or concatenated text.

Completed task/immediate standalone message produces completion. Auth-required, input-required, rejected, failed and canceled tasks emit their original status followed by an explicit adapter error outcome. Premature working EOF/transport loss remains interrupted/unknown. Unsupported subscription of a terminal task and cancellation rejection are explicit outcomes, with no hidden get/unary fallback. Local stream close cancels HTTP; it is not proof of remote task cancellation.

`Next` is pull-driven using `iter.Pull2`. `Close` cancels the underlying request first, joins any in-flight `Next`, then calls iterator stop under the same mutex. Next/stop never run concurrently, and no per-frame producer goroutines or unbounded channels exist. Adapter `Close` cancels its owned invocation lifetime and closes its idle connection pool; consumers still close their streams. Selected operator transports must honor request cancellation.

## Finite transport bounds

Defaults:64KiB event/request body,16MiB total response/stream bytes, one-minute invocation lifetime. Configurable bounds are validated (event/request at most1MiB, stream at most256MiB, lifetime at most10minutes). Default transport disables inherited environment proxies, bounds connection pools/header bytes/header timeout, and disables redirects. An explicit operator transport is preserved. Per-request credentials are restricted to one Authorization and/or X-Api-Key value; authority, protocol/session/idempotency headers cannot be overridden. Tenant propagation from unrelated context is disabled. Errors omit SDK/provider diagnostic bodies, credentials and application input. Exhaustion stops with an unknown/error outcome, never truncated success.

## Verification

Actual official client/server HTTP fixtures cover unary and streaming, exact numeric wire preservation, artifact ordering/append, paused/stopped states, durable restart get/subscribe/cancel, cross-principal denial, no replay after ambiguous connection loss, streaming fallback refusal, redirect/environment-proxy isolation, bounded output and cancellation joining blocked SDK Next. Real SQLite concurrent admission admits one writer. Tests are local; no paid calls or external software provisioning.
